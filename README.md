# 🏪 商业巨子：白手起家

2D 像素风商业模拟网页游戏。纯原生 **HTML / CSS / JavaScript**，不依赖任何构建工具（没有 webpack / npm build），
双击 `index.html` 或丢到任意静态网页托管上就能玩，非常适合部署到 **GitHub Pages**。

三个阶段：**白手起家 → 商业扩张 → 资本帝国**（当前已实现全部三阶段的可玩版本，详见下方）。

---

## 🎮 在线试玩

仓库推到 GitHub 并开启 Pages 后（见下方「部署到 GitHub Pages」），地址形如：

```
https://<你的GitHub用户名>.github.io/<仓库名>/
```

## 💻 本地运行

不需要安装任何依赖，两种方式任选：

1. **直接双击** `index.html` 用浏览器打开（Chrome/Edge/Firefox 均可）。
2. 或起一个本地静态服务器（部分浏览器对 `file://` 下的某些 API 有限制，建议用这种方式）：
   ```bash
   npx http-server -p 8080 -c-1
   # 然后浏览器打开 http://localhost:8080
   ```

```
│   │   ├── config.js            静态配置表：区域/商品/临时工/技能/里程碑/天气（调数值只改这里）
│   │   ├── state.js             存档结构、净资产计算、里程碑判定、读写 localStorage
│   │   ├── economy.js           价格引擎、时间推进、体力精力健康结算、天气
│   │   └── events.js            全局随机事件池（天气/市场/机会/麻烦/个人）
│   ├── phase1/                  第一阶段：白手起家
│   │   ├── jobs.js               临时工 + 技能学习
│   │   ├── trade.js              商品买卖、背包、区域差价

│   │   ├── shop.js               单店经营（货架/声望/员工/每日自动结算）
│   │   └── quests.js             新手任务链、随机委托、成就
│   ├── phase2/biz.js            第二阶段：商业扩张（多店铺/员工/供应商仓库/贷款信用/财报/竞争）
│   ├── phase3/
│   │   ├── market.js            第三阶段金融市场：6只虚拟股票 + 商品期货 + 外汇
│   │   │                        （K线引擎、季度财报、黑天鹅事件、流通盘、保证金交易、跨系统联动）
│   │   └── empire.js            资本帝国：并购/品牌；跨城市/地产等数据结构已预留，未来可直接扩展
│   └── ui/
│       ├── chart.js              Canvas 2D K线图 / 折线图（不依赖第三方图表库）
│       ├── map.js                像素风城市地图渲染与点击交互
│       ├── render.js             把游戏状态渲染到各标签页
│       └── app.js                主控制器：启动流程、导航、所有按钮动作
├── tests/
│   ├── smoke.spec.js            Playwright 冒烟测试：启动→点遍所有标签→交易→打工→摆摊→推进70天→存读档
│   └── balance.spec.js          数值平衡模拟：三种策略（纯打工/倒买倒卖/混合）跑到里程碑1
├── .github/workflows/deploy.yml  推送到 main 自动部署到 GitHub Pages
├── package.json                  仅用于测试依赖（playwright）和本地起服务，游戏本身无需它
└── LICENSE                       MIT
```

**为什么用原生 `<script>` 而不是打包工具？** 为了部署简单：GitHub Pages 直接托管这些静态文件即可运行，
不需要任何 CI 构建步骤。`index.html` 底部的 `<script>` 加载顺序就是模块依赖顺序（core → phase1 → phase2 → phase3 → ui）。

在沙盒环境里用 Playwright 无头浏览器跑过：

- 交易（买入商品）、打工、摆摊开张+营业一轮，均正常结算。
- 金融市场三个子标签（股票/期货/外汇）正常切换，K线图能正确绘制出像素（非空白画布）。
- 连续推进 70 天（`BT.Eco.sleep`），价格引擎/随机事件/K线生成/里程碑判定全程无报错，
  能稳定生成 130+ 根日K线。
- 存档 → 刷新页面 → 读档，天数与状态一致。
- 数值平衡模拟（`tests/balance.spec.js`）：纯打工（码头装卸工）约 9 天、倒买倒卖约 10 天、
  打工+摆摊混合约 16 天，均能达成里程碑1（净资产¥1,000），验证了「没有唯一正确的赚钱方式」的设计目标。
  这些数字可作为后续继续调数值（`js/core/config.js`）的参考基准。

## 🚀 部署到 GitHub Pages

### 方式一：网页操作（推荐，不需要本地 git 环境）

1. 在 GitHub 上新建一个空仓库（**不要**勾选自动生成 README/.gitignore）。
2. 把本项目的全部文件上传上去（网页端「Add file → Upload files」把整个文件夹拖进去，
   或用下面「方式二」的 git 命令）。
3. 进入仓库 **Settings → Pages**，「Build and deployment → Source」选择 **GitHub Actions**。
4. 推送（或上传）到 `main` 分支后，仓库里 `.github/workflows/deploy.yml` 会自动跑起来，
   几十秒后 **Settings → Pages** 页面顶部会出现你的访问地址。

### 方式二：命令行 git push

```bash
# 1. 在 GitHub 新建一个空仓库，例如 business-tycoon，拿到它的地址，比如：
#    https://github.com/<你的用户名>/business-tycoon.git

cd business-tycoon
git remote add origin https://github.com/<你的用户名>/business-tycoon.git
git branch -M main
git push -u origin main

# 2. 然后按「方式一」第3步，把 Pages 的 Source 设为 GitHub Actions 即可自动部署。
```

> 本项目已经在本地执行过 `git init` 并完成了首次提交（`git log` 可查看），
> 你只需要 `git remote add` 指向你自己的仓库然后 `push` 即可，无需重新 init。

## 🕹️ 玩法速览

- **每日时间**：6:00–24:00，每个行动消耗若干小时，超时自动睡觉结算（房租/伙食/熬夜惩罚/商品过期）。
- **三条状态**：体力 / 精力 / 健康，过低会降低打工与摆摊效率。
- **五条起步路径**：临时工、技能工作、低买高卖、摆摊、开店，互相支撑，自由组合。
- **三个里程碑**：净资产 ¥1,000 → 更多交易机会；¥3,000 且生意持续盈利 → 店铺与员工；
  ¥10,000 且生意正常经营 → 自动成立公司，进入第二阶段「商业扩张」。
- **第二阶段**：多店铺、员工招聘培训、批发仓库、银行贷款与信用评级、区域竞争与品牌声望、每日/月度财报。
- **第三阶段金融市场**（开局即可交易，不设资产门槛）：
  - **6 只虚拟股票**（新港重工/滨海地产/云港科技/新辉零售/港源能源/创想医药），覆盖工业、地产、
    科技、零售、能源、医药六个行业，各有不同的**流通盘大小**（0.9亿～8亿股）、波动率与贝塔系数，
    流通盘越小波动越大、也更容易被大额买卖冲击价格；每约45天发布一次**季度财报**（营收/净利/EPS），
    financial surprise 会直接触发股价跳空；并有覆盖六大板块的**突发事件/黑天鹅新闻池**。
  - **商品期货**（大豆/螺纹钢/原油/黄金），5–10倍保证金交易，每日盯市结算，保证金不足会被强制平仓。
  - **外汇**（美元/欧元/日元兑新港元）。
  - **跨系统联动**：第一阶段的商品价格事件（如「蔬菜暴涨」）会直接影响对应期货/个股的价格。
- **解锁条件、数值参数**全部集中在 `js/core/config.js`，调数值不用碰逻辑代码。
- 游戏在每晚睡觉后自动存档到 `localStorage`，也支持 3 个手动存档槽位。

## 🔭 后续可扩展（底层数据结构已预留）

- `js/phase3/empire.js` 里的 `C.CITIES` 数组已预留跨城市经营的结构，新增城市只需往数组里加新区域，
  不需要改动 `Biz` / `Market` 的任何数据结构（它们都按 `regionId` 寻址）。
- 并购（M&A）已有一个轻量实现（竞争对手区域份额收购），房地产投资 / 制造物流可以按同样模式接入。
